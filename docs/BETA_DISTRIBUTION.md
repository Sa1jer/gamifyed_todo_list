# Раздача бета-версий

Приложение не публикуется в магазинах, но сборки уходят знакомым на
тестирование. Отсюда два правила, которые дороже всего нарушить.

## Смена идентификатора уносит данные тестировщика

Android определяет приложение по `applicationId`. Сборка с новым ID — это
**другое приложение**: она встанет рядом со старой, а не поверх неё, и старая
унесёт свои данные, когда её удалят.

`4 сентября 2026` идентификатор сменился с `com.example.todo_list_app` на
`com.rpgtodo.app`. Все, у кого стояла сборка до этой даты, проходят перенос:

1. В старой сборке: **Профиль → Данные → Экспорт**, сохранить файл.
2. Удалить старую сборку.
3. Поставить новую.
4. В новой сборке: **Профиль → Данные → Импорт**, выбрать тот же файл.

Без первого шага данные не вернуть. Предупреждайте до раздачи, а не после.

То же самое касается macOS: контейнер приложения адресуется bundle identifier,
поэтому локальные данные на маке после смены ID тоже нужно перенести экспортом.

Второй раз это произойдёт при переезде на собственный домен (см. ниже), поэтому
менять ID лучше как можно раньше и как можно реже.

## Подпись: ключ теряется — теряются обновления

Android ставит обновление поверх установленного приложения, только если оно
подписано **тем же ключом**. Ключ невосстановим: потеряли — тестировщики
переустанавливают с нуля и снова теряют данные.

Релизная сборка намеренно отказывается собираться без подписи и никогда не
падает обратно на debug-ключ, см. `android/app/build.gradle.kts`.

Ключ создаёт владелец, он же держит пароли:

```bash
keytool -genkey -v -keystore ~/rpg-todo-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias rpg-todo
```

`keytool` спросит пароль, повторит его, а потом задаст несколько вопросов про
имя, организацию, город и код страны. **Это не пароли**, они уходят в открытый
сертификат внутри ключа; можно отвечать как угодно или жать Enter. Код страны —
две буквы, например `RU`.

Пароль **один**. В формате PKCS12, который используется по умолчанию начиная с
JDK 9, у ключа нет отдельного пароля от пароля хранилища — это одно и то же
значение, просто в `key.properties` его нужно указать дважды. Придумывать и
хранить его лучше в менеджере паролей: восстановить его нечем.

Дальше — `android/key.properties`, файл вне репозитория. Шаблон уже лежит рядом:

```bash
cp android/key.properties.example android/key.properties
```

Останется подставить путь к `.jks` и пароль. `storeFile` — полный путь, не
относительный.

`android/.gitignore` закрывает `key.properties`, корневой `.gitignore` — любые
`*.jks` и `*.keystore`. Проверить перед первым коммитом после создания ключа:

```bash
git status --porcelain --ignored | grep -E "key\.properties|\.jks"
```

Строки должны быть помечены как игнорируемые. Резервная копия ключа хранится
там же, где вы храните пароли, а не в проекте.

До появления `key.properties` раздавайте debug-сборку: `flutter build apk
--debug`. Она подписана отладочным ключом, обновляется только поверх такой же
debug-сборки и для магазина непригодна — но для знакомых работает.

## Свой домен

`com.rpgtodo.app` — временный компромисс. Обратный DNS предполагает домен,
которым вы владеете; `rpgtodo.com` вам не принадлежит. Для частной раздачи это
безразлично, для магазина — нет, а после публикации ID не меняется.

Варианты, когда дойдёт до дела:

- Купить домен (`rpgtodo.app`, `rpgtodo.ru`, что-то своё) у любого регистратора
  и взять ID от него. Стоит денег ежегодно, зато ID ваш навсегда.
- Взять `io.github.sa1jer.rpgtodo`. Домен покупать не нужно: право на
  `sa1jer.github.io` подтверждается самим аккаунтом GitHub, и конвенция это
  допускает. Бесплатно и не конфликтует ни с кем.

Решать до первой публикации, не после.
