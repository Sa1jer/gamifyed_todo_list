# Momentum validation diary

This diary is a manual product-validation template for real work. The derived
prototype has no telemetry. No real-use evidence has been collected merely by
implementing or testing it.

## Entry template

- Date:
- Real project or Skill:
- Return Context visible? yes / no
- Momentum message shown:
- Resolver reason shown in debug/test evidence:
- Underlying fact (Stage count/progress, Goal progress, completion, or Minimum
  Action):
- Was the fact correct? yes / partly / no
- Did the wording feel useful? yes / partly / no
- Did it add clarity or only decoration?
- Did it create pressure, urgency, guilt, or streak-like framing? yes / no
- Did it compete visually or conceptually with Next Action? yes / no
- Was the real Next Action still clear within ten seconds? yes / partly / no
- Did it make the real work thread easier to understand or open? yes / partly /
  no
- What real-world change followed, if any?
- Should this signal be kept, rewritten, deprioritised, or removed?
- Would a different truthful signal have been more useful?
- Notes without unnecessary sensitive details:

## Suggested review rhythm

Record voluntary uses across one, three, and seven days of ordinary work. The
goal is not daily engagement. Include false positives, false negatives, cases
where no Momentum appeared, and cases where the absence of a message was the
calmer result.

## Interpretation

Positive evidence means truthful progress is easier to perceive, the current
action remains clear, and the user needs less reconstruction without additional
pressure or planning. Card impressions, app opens, time in app, XP, and task
count are not success measures.

After several entries, decide separately for each reason whether to keep, tune,
or remove it. This diary does not validate Return Context, Next Action, Boot
Entry, a durable Save Point, or any new persisted product concept.
